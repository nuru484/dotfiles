name: detail-views-not-forms
description: Owner rule 30 Sep: a record's details read in a read-only view (dialog for short, page for rich); a form only opens on Edit; rich details (consultation, proposal) get their own page, not a dialog
metadata:
  type: feedback
---

Owner, 30 Sep 2026 (S3 review): "active forms should not be used to display details of any item anywhere"; a detail is a read-only view with an Edit button, and the form appears only after Edit (workflow steps, assignment rules). Rows whose text can truncate (outcome reasons) need a details dialog. Details with more data than a dialog comfortably holds (consultations, fee proposals) get their own page.

**Why:** reading and editing are different acts; a form shown for reading invites accidental change and hides the record's shape.

**How to apply:** every list row opens a read-only view; rich records open a page; Edit swaps to the form. See [[reorder-by-drag-and-click]], [[export-asks-first]].
